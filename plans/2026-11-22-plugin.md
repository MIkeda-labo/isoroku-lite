# isoroku-lite: Claude Code のプラグインにした軽い isoroku（2026-11-22）

ユーザーの指示: isoroku-lite を新しく作る。Claude Code のプラグイン（スキルとフック）にし、コーチ役も使う人自身の Claude Code にやらせる。

## 方針（isoroku から変えること）
- VPS・API キー・Gemma（Ollama）・Next.js の画面・SSH トンネルは使わない。
- コーチは、使う人自身の Claude Code（同じセッション）。フックが「いまの講座・手順・詰まり具合」を Claude に渡し、スキルがコーチの振る舞いを決める。
- 練習中の会話は、もともと使う人の Claude Code を通じて送られている。外へ送る先は増やさない（フックはネットワークを使わない）。
- 残すもの: 講座の JSON（正本は isoroku/lessons。写して使う）、見守りの判定（エラーが続いたら声をかける）、ヒントの段（方向 → 具体例 → 答え）。

## 作り（公式で確かめて決めた。出典は README）
- 配る単位: リポジトリの根に `.claude-plugin/marketplace.json`、プラグイン本体は `plugins/isoroku-lite/`（source に "./" を使う例は公式に無かったので、公式の例どおりサブフォルダにする）。
- `plugins/isoroku-lite/.claude-plugin/plugin.json`、`skills/<名前>/SKILL.md`、`hooks/hooks.json`（"hooks" で包む）、`scripts/*.mjs`、`lessons/*.json`。
- スキル（/isoroku-lite:start・next・hint・status・stop）: 本文の `` !`node "${CLAUDE_PLUGIN_ROOT}/scripts/cli.mjs" …` `` で状態を変え、結果を Claude に渡す。状態は `${CLAUDE_PLUGIN_DATA}/state.json`（作業フォルダごと）。
- フック（SessionStart・UserPromptSubmit・PostToolUse・PostToolUseFailure）: exec 形式で `node ${CLAUDE_PLUGIN_ROOT}/scripts/hook.mjs`。講座を始めていない作業フォルダでは何もしない。
  エラーが2回続いたら（クールダウンつき）、PostToolUseFailure の additionalContext で「方向のヒントを出す」をコーチ（同じ Claude）に頼む。ネットワークは使わない。必ず終了コード 0。

## 結果（2026-11-22）
- 1〜6 済み。テスト 11 件通過。`claude plugin validate` はプラグイン・マーケットプレイスとも通過。
- 本物（claude -p --plugin-dir）で start と見守り（エラー2回 → コーチの一言）を確認。
- スキルの `` !`…` `` は許可が要った → `allowed-tools: Bash(node "${CLAUDE_PLUGIN_ROOT}/scripts/cli.mjs" *)` で通った。
- 残り: ライセンスを決める（ストア申請に必須）、アイコン（任意）、対話の画面・デスクトップ版での確認、git と公開。

## 追加: 時間を区切る見守り（2026-11-22、ユーザー「isoroku のように時間を区切って読みに行く見守りも足して」）
- /loop ではなく、プラグインのモニター（monitors/monitors.json、when: on-skill-invoke:start）にする。
  理由: 自動で始まる・15秒ごとでも何も起きなければトークンを使わない・公式も Monitor のほうが効率的と書いている（scheduled-tasks）。
- 手順: (1) フックが transcript_path を状態に覚える (2) scripts/monitor.mjs: 15秒ごとに記録の末尾を読み、isoroku の判定（repeated_error・stuck_idle、resolved・already_spoke・cooldown・1時間6回）を移す。声をかけるときだけ1行出す
  (3) クールダウンはフックと共有 (4) テスト (5) validate (6) 対話の画面（tmux）で、エラーのあと止まると声がかかるかを確かめる（-p ではモニターが動かない）
- 確かめが要ること: モニターの通知が、手の空いた Claude を起こすか（公式に書かれていない）。
